# OpenStack Gerrit Topic Analytics — Pilot Pipeline

A two-script Python pipeline that collects raw Gerrit change data from
[review.opendev.org](https://review.opendev.org) and aggregates it into a
topic-level dataset for exploratory analysis.

---

## Requirements

- Python 3.11+
- Internet access to `review.opendev.org` (public, no auth required)

---

## Quick Start

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. (Optional) Verify the first collection URL without fetching
python collect_changes.py --dry-run

# 3. Collect raw changes (~minutes to hours depending on scope)
python collect_changes.py

# 4. Build the topic-level dataset
python build_topic_dataset.py
```

Outputs:
- `raw_data/` — raw JSON, one file per project × status × page
- `topics_dataset.csv` — topic-level metrics table
- `topics_dataset.parquet` — same data in Parquet (Snappy-compressed)

---

## Script Reference

### `collect_changes.py`

| Constant | Default | Purpose |
|---|---|---|
| `BASE_URL` | `https://review.opendev.org` | Gerrit REST endpoint |
| `PROJECTS` | nova, neutron, cinder, keystone | Projects to collect |
| `DATE_FROM` | `2023-01-01` | Earliest `created` date |
| `STATUSES` | merged, abandoned, open | Change statuses |
| `PAGE_SIZE` | `500` | Results per request |
| `REQUEST_DELAY` | `0.75` s | Sleep between requests |
| `SAFETY_CEILING` | `50 000` | Warn + ask before exceeding |
| `RAW_DATA_DIR` | `./raw_data` | Output root |

**Pagination**: uses `_more_changes` flag + `before:<updated>` to chain pages.  
**Resumability**: existing page files are skipped automatically on re-runs.  
**Safety**: if the running total exceeds `SAFETY_CEILING`, the script prints a warning and asks before continuing.

```
raw_data/
└── openstack_nova/
    ├── merged/
    │   ├── page_1.json
    │   ├── page_2.json
    │   └── …
    ├── abandoned/
    └── open/
```

### `build_topic_dataset.py`

| Constant | Default | Purpose |
|---|---|---|
| `RAW_DATA_DIR` | `./raw_data` | Input root |
| `OUTPUT_CSV` | `topics_dataset.csv` | CSV output path |
| `OUTPUT_PARQUET` | `topics_dataset.parquet` | Parquet output path |
| `LARGE_TOPIC_THRESHOLD` | `50` | Flag topics above this count |
| `STALE_OPEN_DAYS` | `90` | Days without activity → stale_open |
| `CI_TAG_PREFIXES` | `autogenerated:zuul` | Tag prefix to detect CI bots |

## Output Schema

| Column | Type | Description |
|---|---|---|
| `topic_id` | string | Gerrit `topic` field value |
| `n_changes` | int | Number of changes in the topic |
| `n_repos` | int | Distinct Gerrit projects (repos) |
| `n_branches` | int | Distinct target branches |
| `total_revisions` | int | Sum of patchset counts |
| `total_messages` | int | Sum of review message counts |
| `n_reviewers` | int | Distinct reviewer account IDs |
| `created_at` | ISO 8601 | Earliest change creation timestamp |
| `last_updated_at` | ISO 8601 | Latest change update timestamp |
| `time_to_completion_hours` | float / null | `max(submitted) − min(created)` in hours; only set when **all** changes are merged |
| `n_merged` | int | Count of merged changes |
| `n_abandoned` | int | Count of abandoned changes |
| `n_open` | int | Count of open changes |
| `outcome` | enum | `merged` / `abandoned` / `mixed` / `stale_open` |
| `ci_rerun_verified_drops` | int | Verified label regressions (positive → ≤0) by CI bot accounts |
| `ci_rerun_recheck_msgs` | int | Messages containing the literal string `"recheck"` |

### Outcome Classification

| Value | Condition |
|---|---|
| `merged` | All changes merged |
| `abandoned` | All changes abandoned |
| `stale_open` | ≥1 open change AND last activity > 90 days ago |
| `mixed` | Any other combination |

---

## CI Re-run Detection

The pipeline uses two independent heuristics and reports them in **separate columns** so you can cross-check them:

1. **`ci_rerun_verified_drops`** — counts times the Verified label transitions from a positive value back to ≤ 0 for votes cast by bot accounts.  Bot account IDs are auto-discovered by looking for label votes with a tag prefixed `autogenerated:zuul`.

2. **`ci_rerun_recheck_msgs`** — counts review messages that contain the word `recheck` (human-initiated re-triggers).

The script prints all discovered bot account IDs at the end so you can manually verify them on Gerrit.

## Extending the Pilot

**Add more projects** — edit the `PROJECTS` list in `collect_changes.py`.  
**Change the date window** — update `DATE_FROM`.  
**Change the safety ceiling** — update `SAFETY_CEILING`.  
**Add more CI bot tag prefixes** — extend `CI_TAG_PREFIXES` in `build_topic_dataset.py`.

## Troubleshooting

| Symptom | Likely Cause | Fix |
|---|---|---|
| `FileNotFoundError: No page_*.json files` | Collection not run yet | Run `collect_changes.py` first |
| HTTP 429 / connection errors | Rate limit hit | Increase `REQUEST_DELAY` |
| Empty `topics_dataset.*` | No changes have a `topic` field | Normal for un-tagged changes — not a bug |
| Parquet write fails | `pyarrow` not installed | `pip install pyarrow` |
